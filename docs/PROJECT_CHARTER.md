# TaskPulse 项目章程

## 1. 项目名称

**TaskPulse：基于 Go 的可靠异步任务执行系统**

首个验证应用：

**URL Inspector：批量 URL 检测与网页元数据采集（早期验证负载）**

当前的真实接入负载是 MemoBridge 的 `memobridge.semantic_profile`。URL Inspector 仍用于验证通用 Executor 和并发行为。

## 2. 一句话说明

TaskPulse 接收耗时或批量任务，将任务拆分后交给受控数量的 Worker 异步执行，并提供状态追踪、超时取消、失败重试、崩溃恢复和可观测能力。

## 3. 要解决的问题

同步 HTTP 请求不适合直接承载大量耗时且结果不确定的工作。

以批量 URL 检测为例：

- 每个 URL 的响应时间不同
- URL 可能超时、重定向或访问失败
- 一批 URL 中可能只有部分失败
- 同时发出过多请求会耗尽本机和目标站点资源
- 用户需要知道当前进度和每个 URL 的结果
- Worker 或服务崩溃后，未完成任务不能永久丢失
- 网络重试可能导致同一个任务被重复执行

TaskPulse 的目标是把这些问题从同步请求中分离出来，形成可靠、可恢复、可观察的后台执行链路。

## 4. 核心使用流程

```text
业务系统提交一批业务引用
→ API 为每个独立工作项创建任务
→ API 立即返回 task_id
→ Worker 在并发限制下领取并执行子任务
→ 系统记录状态码、耗时、重定向、标题或错误
→ 临时错误按策略重试
→ 用户查询任务进度和子任务结果
→ 任务最终成功、部分成功、失败或取消
```

## 5. 项目价值

URL 检测只是用来验证系统的真实负载，不是项目的全部价值。

项目重点证明以下后端能力：

- Go 并发控制
- 任务状态机
- 有界队列与背压
- 超时与协作式取消
- 错误分类与指数退避重试
- 幂等与至少执行一次语义
- Worker 租约与崩溃恢复
- 多 Worker 竞争领取任务
- 数据库事务和行锁
- 优雅关闭
- 日志、指标、性能分析和压力测试

## 6. 系统边界

### TaskPulse Core 负责

- 通用任务生命周期（不理解 SourceItem、Prompt 或 LLM 输出）
- 任务保存与领取
- Worker 并发执行
- 重试、取消和恢复
- 事件记录
- 指标和运行状态

### URL Inspector 负责

- URL 格式校验
- HTTP 请求
- 重定向处理
- 网页元数据提取
- HTTP 错误分类

### 第一版不负责

- 通用工作流编排
- 任意代码执行
- 多 Agent 协作
- 插件市场
- 复杂微服务体系
- 自研 Raft 或注册中心
- 直接访问 MemoBridge 数据库

## 7. 第一版完成标准

第一版必须做到：

- 创建批量 URL 检测任务
- 查询任务和子任务结果
- 使用固定大小 Worker Pool
- 支持 HTTP 超时和任务取消
- 支持部分成功
- 对可恢复错误进行有限重试
- 持久化任务状态
- Worker 崩溃后可以恢复未完成任务
- 提供结构化日志和基础 Prometheus 指标
- 使用 Docker Compose 启动
- 形成压力测试和故障测试报告

## 8. 技术演进原则

项目按照问题驱动演进：

```text
内存 Store
→ 发现重启丢数据和多实例无法共享
→ 引入 MySQL

直接创建 goroutine
→ 发现并发不可控
→ 引入有界队列和 Worker Pool

任务标记 running
→ 发现 Worker 崩溃后任务无法恢复
→ 引入租约和过期重新领取

失败立即重试
→ 发现故障被放大
→ 引入错误分类和指数退避

增加 Worker
→ 发现吞吐不一定持续增长
→ 使用指标、pprof 和压测定位瓶颈
```

Redis、Kafka、Kubernetes 等组件只有在现有方案出现并被验证的问题后才引入。

## 9. 项目成功的证据

项目不能只用功能列表证明完成，还必须提供：

- 单元测试和数据库集成测试
- `go test -race` 并发检查
- Worker 崩溃恢复实验
- 重复执行和幂等实验
- 不同 Worker 数量下的吞吐对比
- P50、P95、P99 延迟
- 队列积压、失败率和重试率指标
- CPU、内存和 goroutine 分析
- 架构决策与问题实验文档

## 10. 秋招项目表达

> TaskPulse 是我使用 Go 开发的可靠异步任务执行系统。我选择批量 URL 检测作为首个真实负载，因为网络请求存在耗时不确定、超时、部分失败和重试等问题。系统通过有界 Worker Pool 控制并发，使用任务状态机管理生命周期，并通过 MySQL 持久化队列、行锁领取、Worker 租约和幂等机制处理崩溃恢复与重复执行。最后使用 Prometheus、pprof 和压力测试验证系统吞吐、延迟和故障恢复能力。
